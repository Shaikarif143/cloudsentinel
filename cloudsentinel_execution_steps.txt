CLOUDSENTINEL - EXECUTION STEPS ON AWS
========================================

PREREQUISITES
--------------
- AWS account with admin access (or scoped permissions for IAM, Lambda,
  DynamoDB, S3, VPC, CloudTrail, Config, Security Hub, EventBridge, SNS)
- AWS CLI configured (aws configure) with your access key/secret
- Terraform >= 1.6 installed
- Python 3.12, Node.js 20, npm installed
- The cloudsentinel project extracted locally


STEP 1 - BOOTSTRAP TERRAFORM REMOTE STATE (one-time, manual)
--------------------------------------------------------------
Terraform needs an S3 bucket + DynamoDB table to store/lock state
before you can run "terraform init".

  # Create state bucket
  aws s3api create-bucket \
    --bucket cloudsentinel-tf-state-$(aws sts get-caller-identity --query Account --output text) \
    --region ap-south-1 \
    --create-bucket-configuration LocationConstraint=ap-south-1

  aws s3api put-bucket-versioning \
    --bucket cloudsentinel-tf-state-$(aws sts get-caller-identity --query Account --output text) \
    --versioning-configuration Status=Enabled

  # Create lock table
  aws dynamodb create-table \
    --table-name cloudsentinel-tf-locks \
    --attribute-definitions AttributeName=LockID,AttributeType=S \
    --key-schema AttributeName=LockID,KeyType=HASH \
    --billing-mode PAY_PER_REQUEST \
    --region ap-south-1


STEP 2 - INITIALIZE TERRAFORM
-------------------------------
  cd terraform

  terraform init \
    -backend-config="bucket=cloudsentinel-tf-state-<your-account-id>" \
    -backend-config="key=cloudsentinel/terraform.tfstate" \
    -backend-config="region=ap-south-1" \
    -backend-config="dynamodb_table=cloudsentinel-tf-locks"


STEP 3 - EDIT VARIABLES
-------------------------
Open environments/dev.tfvars and set a real email:

  alert_email = "your-actual-email@gmail.com"


STEP 4 - PLAN AND APPLY
-------------------------
  terraform plan  -var-file=environments/dev.tfvars -out=tfplan
  terraform apply tfplan

This provisions: VPC, DynamoDB tables, S3 log bucket, CloudTrail, SNS
topic (confirm the email subscription from your inbox), CloudWatch,
AWS Config, Security Hub, and both Lambda functions with the
EventBridge schedule.

Takes about 5-10 minutes (NAT Gateway is the slowest resource).


STEP 5 - VERIFY THE SCANNER IS RUNNING
-----------------------------------------
  # Check the schedule fired
  aws events list-rules --name-prefix cloudsentinel

  # Manually trigger a scan
  aws lambda invoke \
    --function-name cloudsentinel-dev-scanner \
    --payload '{}' \
    --cli-binary-format raw-in-base64-out \
    /tmp/response.json
  cat /tmp/response.json

  # Check findings landed in DynamoDB
  aws dynamodb scan --table-name cloudsentinel-dev-findings --max-items 5

You should also get an SNS email with the scan summary.


STEP 6 - RUN TESTS LOCALLY (optional but good for interviews)
------------------------------------------------------------------
  cd ../backend
  pip install pytest boto3 --break-system-packages
  pytest tests -v


STEP 7 - RUN THE DASHBOARD LOCALLY
-------------------------------------
  cd ../frontend
  npm install
  npm run dev

Opens on http://localhost:5173 - it will show demo data unless you
wire up an API Gateway (see Step 9).


STEP 8 - SET UP CI/CD (GITHUB ACTIONS)
------------------------------------------
1. Push the repo to GitHub.
2. Create an IAM OIDC role for GitHub Actions to assume (trust policy
   for token.actions.githubusercontent.com).
3. Add repo secrets: AWS_DEPLOY_ROLE_ARN, TF_STATE_BUCKET,
   TF_LOCK_TABLE, CLOUDSENTINEL_API_URL, DASHBOARD_BUCKET,
   CLOUDFRONT_DISTRIBUTION_ID.
4. Push to main - the pipeline runs tests -> terraform validate ->
   Checkov/tfsec -> deploy.


STEP 9 - (OPTIONAL NEXT STEP) WIRE UP THE API GATEWAY
-----------------------------------------------------------
The dashboard currently uses mock data. To go fully live, add a small
Lambda + API Gateway that reads the two DynamoDB tables and returns
JSON matching frontend/src/api.js's expected shape, then set
VITE_API_BASE_URL to its endpoint.


STEP 10 - TEAR DOWN (when done, to avoid charges)
------------------------------------------------------
  cd terraform
  terraform destroy -var-file=environments/dev.tfvars

WARNING: NAT Gateway and CloudTrail incur ongoing cost - don't forget
this step once you're done demoing it.
